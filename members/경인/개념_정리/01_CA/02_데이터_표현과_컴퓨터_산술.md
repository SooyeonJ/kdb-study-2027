# 02. 데이터 표현과 컴퓨터 산술

[목차로 돌아가기](./README.md) · [이전: 컴퓨터 구조의 기초](./01_컴퓨터_구조의_기초.md) · [다음: 논리회로](./03_논리회로.md)

선수 개념 : 비트와 바이트, 정수·소수의 자릿값.

## 1. 본문 개념 설명

### 1.1 진법과 자릿값

- r진법 : 한 자리에 0부터 r-1까지의 숫자를 사용하는 수 표현 방식.
- 자릿값 : 각 자리에 부여되는 r의 거듭제곱 가중치. 소수점 바로 왼쪽은 r⁰, 바로 오른쪽은 r⁻¹.
- 최상위 비트(MSB, Most Significant Bit) : 비트열의 맨 왼쪽 비트.
- 최하위 비트(LSB, Least Significant Bit) : 비트열의 맨 오른쪽 비트.

```text
(1011.01)₂
= 1×2³ + 0×2² + 1×2¹ + 1×2⁰ + 0×2⁻¹ + 1×2⁻²
= 8 + 2 + 1 + 0.25
= (11.25)₁₀
```

16진법은 10~15를 A~F로 나타낸다. 따라서 `(2F)₁₆ = 2×16 + 15 = 47`이다. 프로그래밍에서는 16진수 앞에 `0x`, 2진수 앞에 `0b`를 붙여 구분하기도 한다.

| 10진수 | 2진수 | 16진수 | 10진수 | 2진수 | 16진수 |
|---:|:---:|:---:|---:|:---:|:---:|
| 0 | 0000 | 0 | 8 | 1000 | 8 |
| 1 | 0001 | 1 | 9 | 1001 | 9 |
| 2 | 0010 | 2 | 10 | 1010 | A |
| 3 | 0011 | 3 | 11 | 1011 | B |
| 4 | 0100 | 4 | 12 | 1100 | C |
| 5 | 0101 | 5 | 13 | 1101 | D |
| 6 | 0110 | 6 | 14 | 1110 | E |
| 7 | 0111 | 7 | 15 | 1111 | F |

### 1.2 진법 변환

정수 변환 : r로 반복해서 나눈 뒤 나머지를 역순으로 나열.

```text
45 ÷ 2 = 22 … 1
22 ÷ 2 = 11 … 0
11 ÷ 2 =  5 … 1
 5 ÷ 2 =  2 … 1
 2 ÷ 2 =  1 … 0
 1 ÷ 2 =  0 … 1

아래에서 위로 읽으면 (101101)₂
```

소수 변환 : 소수 부분에 r을 반복해서 곱한 뒤 정수 부분을 나온 순서대로 나열. 다음 단계에는 소수 부분만 사용.

```text
0.625 × 2 = 1.25 → 정수 부분 1
0.25  × 2 = 0.5  → 정수 부분 0
0.5   × 2 = 1.0  → 정수 부분 1, 소수 부분이 0이므로 종료

(0.625)₁₀ = (0.101)₂
```

10진 유한소수가 항상 2진 유한소수가 되는 것은 아니다. 예를 들어 0.1은 2진법에서 무한히 반복된다. 기약분수의 분모가 2의 거듭제곱인 경우에만 2진 유한소수로 표현할 수 있다.

2진수 ↔ 8진수·16진수 : 3비트 또는 4비트씩 묶어 변환. `8=2³`, `16=2⁴`이므로 각 묶음이 한 자리에 대응한다.

- 정수 부분: 소수점에서 왼쪽으로 묶고, 부족하면 맨 왼쪽에 0을 채운다.
- 소수 부분: 소수점에서 오른쪽으로 묶고, 부족하면 맨 오른쪽에 0을 채운다.

```text
(101101.011)₂
= (101 101 . 011)₂ = (55.3)₈
= (0010 1101 . 0110)₂ = (2D.6)₁₆
```

소수 부분의 앞에 0을 끼워 넣으면 값이 바뀐다. 묶음 맞추기는 소수점에서 먼 쪽에만 한다.

### 1.3 부호 없는 정수

부호 없는 정수(Unsigned Integer) : 부호 비트 없이 모든 비트를 크기 표현에 사용하는 정수 형식.

- n비트 범위 : `0 ~ 2ⁿ-1`
- 8비트 범위 : `00000000 ~ 11111111`, 즉 0~255

표현 가능한 비트열의 개수는 2ⁿ개지만 최댓값은 2ⁿ-1이다. 0이 한 가지를 차지하기 때문이다.

### 1.4 부호 있는 정수의 세 가지 표현

기준 : 고정된 n비트. 비트 수가 달라지면 보수도 달라진다.

부호와 절댓값(Sign-Magnitude) : 최상위 비트는 부호, 나머지 비트는 절댓값을 나타내는 표현 방식.

- 부호 비트 : 0은 양수, 1은 음수
- 8비트 예 : +5=`00000101`, -5=`10000101`
- 0의 표현 : +0=`00000000`, -0=`10000000`

1의 보수(Ones' Complement) : 양수의 모든 비트를 반전하여 음수를 나타내는 표현 방식.

- 8비트 예 : +5=`00000101` → -5=`11111010`
- 0의 표현 : +0=`00000000`, -0=`11111111`

2의 보수(Two's Complement) : 양수의 모든 비트를 반전하고 1을 더하여 음수를 나타내는 표현 방식.

- 8비트 예 : -5=`11111010 + 1 = 11111011`
- 0의 표현 : 하나
- 범위 특징 : 음수 쪽에 한 값을 더 표현 가능

| 표현 방식 | n비트 범위 | 8비트 범위 | 0의 표현 |
|---|---|---|---|
| 부호 없는 정수 | 0 ~ 2ⁿ-1 | 0 ~ 255 | 1개 |
| 부호와 절댓값 | -(2ⁿ⁻¹-1) ~ 2ⁿ⁻¹-1 | -127 ~ 127 | 2개 |
| 1의 보수 | -(2ⁿ⁻¹-1) ~ 2ⁿ⁻¹-1 | -127 ~ 127 | 2개 |
| 2의 보수 | -2ⁿ⁻¹ ~ 2ⁿ⁻¹-1 | -128 ~ 127 | 1개 |

2의 보수 값은 최상위 비트의 가중치만 음수로 두어 바로 계산할 수도 있다.

```text
(11111011)₂를 8비트 2의 보수로 해석
= -128 + 64 + 32 + 16 + 8 + 0 + 2 + 1
= -5
```

또는 부호 없는 값 251에서 2⁸을 빼 `251 - 256 = -5`로 구한다. 이 방법은 최상위 비트가 1인 2의 보수 수에 적용한다.

최솟값 -128의 비트열은 `10000000`이다. 이를 반전하고 1을 더해도 8비트 결과는 다시 `10000000`이다. +128이 8비트 부호 있는 범위에 없기 때문에, 최솟값의 부호를 바꾸는 연산은 오버플로를 일으킨다.

#### 예제: 하나의 비트열을 다르게 읽기

대상 : 8비트 `10000101`. 표현 방식에 따른 값 비교.

| 해석 방식 | 계산 | 값 |
|---|---|---:|
| 부호 없음 | 128+4+1 | 133 |
| 부호와 절댓값 | 부호 1, 크기 0000101 | -5 |
| 1의 보수 | 반전하면 01111010 = 122 | -122 |
| 2의 보수 | 133-256 | -123 |

‘맨 앞이 1이므로 나머지 비트에 마이너스를 붙인다’는 방법은 부호와 절댓값 표현에만 맞는다.

#### 예제: 비트 수에 따른 표현 범위

서로 다른 상태 1,000개를 구분하려면 최소 몇 비트가 필요할까?

```text
2⁹ = 512 < 1,000
2¹⁰ = 1,024 ≥ 1,000
따라서 최소 10비트
```

이는 ‘정수 1,000까지 부호 있게 저장한다’는 조건과 다르다. 2의 보수로 +1,000을 표현하려면 `2ⁿ⁻¹-1 ≥ 1,000`이어야 하므로 최소 11비트가 필요하다.

### 1.5 보수와 뺄셈

n자리 r진수 N에 대해 `(r-1)의 보수 = (rⁿ-1)-N`, `r의 보수 = rⁿ-N`이다. r의 보수는 n자리 결과만 남기는 방식으로 생각하며, N=0의 결과는 0으로 처리한다. 이진법에서는 각각 1의 보수와 2의 보수에 해당한다.

2의 보수를 이용하면 `A-B`를 `A+(-B)`로 계산할 수 있다. 뺄셈을 덧셈 회로로 처리할 수 있다는 점에서 중요하다.

```text
8비트에서 13 - 5

  13 :   00001101
  -5 : + 11111011
       ----------
       1 00001000

8비트 밖의 자리올림을 버리면 00001000 = 8
```

2의 보수 연산에서 비트 폭 밖의 자리올림을 버린다고 해서 오버플로가 항상 없는 것은 아니다. 결과가 해석 방식의 범위에 들어가는지는 따로 확인해야 한다.

순환 자리올림(End-Around Carry) : 최상위 자리 밖으로 나온 자리올림을 최하위 자리에 다시 더하는 처리.

1의 보수 덧셈에서 사용하는 규칙으로, 바깥 자리올림을 버리는 2의 보수 연산과 구분한다.

```text
4비트 1의 보수에서 5 + (-3)
0101 + 1100 = 1 0001
0001 + 1 = 0010 → 2
```

#### 예제: 8비트 2의 보수로 18-27

```text
 27 = 00011011
반전  11100100
+ 1   11100101 → -27

 18   00010010
-27 + 11100101
      --------
      11110111
```

결과의 최상위 비트가 1이므로 음수다. 부호 없는 값으로는 247이므로 `247-256=-9`다. 양수와 음수를 더한 것이므로 부호 있는 덧셈 오버플로는 없다.

### 1.6 자리올림과 오버플로

오버플로(Overflow) : 계산의 실제 결과가 정해진 비트 수의 표현 범위를 벗어나는 현상.

**부호 없는 연산과 2의 보수 연산은 판별 기준이 다르다.**

- 부호 없는 덧셈: n비트 밖으로 자리올림이 나가면 범위를 넘는다.
- 2의 보수 덧셈: 같은 부호끼리 더했는데 결과의 부호가 달라지면 오버플로다.
- 2의 보수 덧셈에서 서로 다른 부호끼리 더하면 오버플로가 발생하지 않는다.

```text
8비트 2의 보수: 100 + 60
01100100 + 00111100 = 10100000

실제 합 160은 -128~127 밖에 있다.
비트열 10100000을 2의 보수로 읽으면 -96이다.
양수 + 양수의 결과가 음수가 되었으므로 오버플로다.
```

반대로 `11111111 + 00000001 = 1 00000000`은 바깥 자리올림이 있다. 부호 없는 해석에서는 `255+1`이므로 오버플로지만, 2의 보수 해석에서는 `-1+1=0`이므로 부호 있는 오버플로가 아니다.

2의 보수 뺄셈 `A-B`에서는 A와 B의 부호가 다르고, 결과의 부호가 A와 다르면 오버플로다. 예를 들어 8비트에서 `127-(-1)`은 실제 값 128을 담지 못한다.

### 1.7 비트 확장과 시프트

- 0 확장(Zero Extension) : 왼쪽을 0으로 채워 비트 수를 늘리는 방법. 부호 없는 정수의 값 유지에 사용.
- 부호 확장(Sign Extension) : 원래 부호 비트를 왼쪽에 복제하는 방법. 2의 보수 정수의 값 유지에 사용.

```text
4비트 2의 보수 -3 : 1101
8비트로 부호 확장 : 11111101 → -3
잘못된 0 확장    : 00001101 → +13
```

- 논리 시프트 : 비트를 이동하고 빈 자리를 0으로 채우는 연산.
- 산술 오른쪽 시프트 : 오른쪽으로 이동하면서 왼쪽 빈 자리를 부호 비트로 채우는 연산.

왼쪽으로 k비트 이동한 결과는 표현 범위를 넘지 않는 경우 원래 값의 2ᵏ배다.

음수의 산술 오른쪽 시프트를 단순히 ‘0을 향해 버리는 나눗셈’이라고 외우면 틀릴 수 있다. 8비트 -3인 `11111101`을 한 비트 산술 오른쪽 시프트하면 `11111110`, 즉 -2가 된다. 이는 -3/2를 음의 무한대 방향으로 내림한 값이다.

### 1.8 고정소수점

고정소수점(Fixed-Point) : 소수점 위치를 고정하고 정수 비트열에 일정한 배율을 적용하는 수 표현 방식.

소수점 자체를 저장하는 것이 아니라, 저장된 정수를 약속된 배율로 해석한다.

소수부가 f비트라면 저장된 정수 I의 실제 값은 `I × 2⁻ᶠ`다. I를 부호 없는 정수로 읽는지, 2의 보수 정수로 읽는지도 정해야 한다.

예를 들어 8비트 2의 보수 정수에 소수부 4비트를 배정하면 다음과 같다.

```text
저장 비트열 00110100 → 정수로는 52
실제 값 = 52 / 16 = 3.25

표현 간격 = 1/16 = 0.0625
최솟값 = -128/16 = -8
최댓값 = 127/16 = 7.9375
```

같은 비트 수에서 소수부를 늘리면 표현 간격은 좁아지지만 표현 범위는 줄어든다. Q 형식 표기는 부호 비트를 정수부에 포함하는지 자료마다 다를 수 있으므로, 문제의 비트 배분을 먼저 확인한다.

### 1.9 부동소수점과 IEEE 754

부동소수점(Floating-Point) : 부호·유효숫자·지수를 나누어 저장하는 수 표현 방식.

`1.101 × 2³`처럼 지수로 소수점 위치를 조절해 넓은 범위를 표현한다. 유효숫자의 비트 수가 제한되므로 모든 실수를 정확하게 저장할 수는 없다.

IEEE 754의 대표적인 이진 형식은 다음과 같다.

| 형식 | 전체 | 부호 s | 지수 필드 E | 소수 필드 F | 지수 바이어스 |
|---|---:|---:|---:|---:|---:|
| binary32, 단정도 | 32비트 | 1 | 8 | 23 | 127 |
| binary64, 배정도 | 64비트 | 1 | 11 | 52 | 1023 |

정규수의 값은 다음 식으로 읽는다.

```text
(-1)ˢ × (1.F)₂ × 2^(E - 바이어스)
```

E는 지수 필드를 부호 없는 정수로 읽은 값이다. 지수를 2의 보수로 저장하는 것이 아니라 바이어스를 더해 저장한다. 정규수의 맨 앞 1은 생략되므로 단정도의 유효숫자 정밀도는 23비트가 아니라 24비트다. 소수 필드 F는 흔히 가수부라고도 부르지만, 실제 유효숫자는 생략된 1을 포함한다.

지수 필드가 모두 0이거나 모두 1이면 위의 정규수 식을 그대로 적용하지 않는다.

| 지수 필드 | 소수 필드 | 의미 |
|---|---|---|
| 모두 0 | 모두 0 | +0 또는 -0 |
| 모두 0 | 0이 아님 | 비정규수(Subnormal): `(-1)ˢ × (0.F)₂ × 2^(1-바이어스)` |
| 0과 최댓값 사이 | 어떤 값이든 | 정규수 |
| 모두 1 | 모두 0 | +∞ 또는 -∞ |
| 모두 1 | 0이 아님 | NaN(Not a Number) |

단정도의 정규수 실제 지수 범위는 -126~127이다. 비정규수는 선행 1을 사용하지 않아 0에 더 가까운 값을 표현한다. 단정도 최소 양의 정규수는 2⁻¹²⁶, 최소 양의 비정규수는 2⁻¹⁴⁹이다. 형식과 특수값은 [Illinois CS 357 부동소수점 자료](https://cs357.cs.illinois.edu/notes/ref-4-fp.html)를 참고했다.

표현 가능한 두 수 사이에 있는 값은 반올림해야 한다. 대표적인 기본 반올림 방식은 가장 가까운 값으로 반올림하되 정확히 중간이면 마지막 유효 비트가 짝수인 쪽을 선택하는 방식이다. 따라서 유한한 비트로 저장하는 과정에서 오차가 생길 수 있고, 연산 순서에 따라 결과가 달라질 수도 있다.

#### 예제: 13.25를 IEEE 754 단정도로 표현

먼저 2진수로 바꾼다.

```text
13 = (1101)₂, 0.25 = (0.01)₂
13.25 = (1101.01)₂ = (1.10101)₂ × 2³
```

양수이므로 부호 s는 0이다. 실제 지수 3에 바이어스 127을 더한 130을 지수 필드에 저장한다. `130 = (10000010)₂`다. 소수 필드에는 선행 1을 제외한 `10101`을 넣고 23비트가 될 때까지 오른쪽에 0을 채운다.

```text
부호   지수          소수 필드
 0   10000010   10101000000000000000000

전체: 0100 0001 0101 0100 0000 0000 0000 0000
16진수: 0x41540000
```

검산하면 `(1 + 1/2 + 1/8 + 1/32) × 2³ = 1.65625 × 8 = 13.25`다.

### 1.10 BCD와 문자 코드

8421 BCD(Binary-Coded Decimal) : 10진수의 각 자리를 4비트로 따로 표현하는 코드.

- 유효 코드 : `0000~1001`
- 미사용 코드 : `1010~1111`

```text
10진수 59
일반 2진수 : 00111011
8421 BCD   : 0101 1001  ← 5와 9를 각각 표현
```

BCD 한 자리의 덧셈 결과가 9를 넘거나 4비트 밖으로 자리올림이 발생하면 `0110`을 더해 보정한다. 예를 들어 `5+7 = 1100`에 `0110`을 더하면 `0001 0010`, 즉 BCD 12가 된다.

ASCII(American Standard Code for Information Interchange) : 7비트로 128개의 제어 문자와 문자를 나타내는 문자 코드.

저장 시 8비트 바이트를 사용할 수 있지만 코드 자체는 7비트다. 문자 `'0'`의 ASCII 값은 48이며 정수 0과 다르다.

- Unicode : 문자에 코드 포인트를 부여하는 문자 체계.
- UTF-8·UTF-16 : 유니코드 값을 코드 단위로 표현하는 인코딩 방식.

| 구분 | 표현 방식 | 주의할 점 |
|---|---|---|
| ASCII | 7비트 코드 | 한글을 표현하지 못한다. |
| UTF-8 | 유니코드 스칼라 값당 1~4바이트 | ASCII 범위는 같은 값의 1바이트로 표현한다. |
| UTF-16 | 유니코드 스칼라 값당 16비트 코드 단위 1개 또는 2개 | 항상 문자당 2바이트인 것은 아니다. |

화면에서 한 글자로 보이는 것이 여러 코드 포인트의 조합일 수도 있다. 따라서 글자 수, 코드 포인트 수, 바이트 수를 항상 같다고 보면 안 된다. 인코딩 길이와 코드 단위 구분은 [Unicode 공식 FAQ](https://www.unicode.org/faq/utf_bom.html)를 참고했다.

### 1.11 바이트 순서: 엔디언

엔디언(Endianness) : 여러 바이트로 이루어진 값을 메모리에 저장할 때의 바이트 순서.

- 빅 엔디언 : 최상위 바이트를 낮은 주소에 저장
- 리틀 엔디언 : 최하위 바이트를 낮은 주소에 저장

바이트 내부의 비트 순서는 뒤집지 않는다.

32비트 값 `0x12345678`을 주소 100부터 저장하면 다음과 같다.

| 주소 | 100 | 101 | 102 | 103 |
|---|---|---|---|---|
| 빅 엔디언 | 12 | 34 | 56 | 78 |
| 리틀 엔디언 | 78 | 56 | 34 | 12 |

표의 값은 각각 16진수 한 바이트다. 해당 엔디언 규칙에 따라 읽으면 두 방식 모두 원래 값으로 복원된다.

## 2. 핵심 비교와 혼동 포인트

| 구분 | 확인할 내용 |
|---|---|
| 2ⁿ개와 2ⁿ-1 | 전자는 비트열 개수, 후자는 n비트 부호 없는 최댓값이다. |
| 1의 보수와 2의 보수 | 반전만 하는지, 반전 후 1을 더하는지 구분한다. |
| 부호 비트 | 2의 보수에서 나머지 비트가 음수의 절댓값을 뜻하지 않는다. |
| 자리올림과 오버플로 | 부호 있는 연산에서는 최종 자리올림만으로 판별하지 않는다. |
| 정수의 0과 부동소수점의 0 | 2의 보수 정수의 0은 하나지만 IEEE 754에는 +0과 -0이 있다. |
| 지수 필드와 실제 지수 | 정규수는 저장된 E에서 바이어스를 뺀다. |
| 소수 필드와 정밀도 | 단정도 정규수는 선행 1을 포함해 24비트 정밀도다. |
| 일반 2진수와 BCD | BCD는 10진수 각 자리를 따로 변환한다. |
| Unicode와 UTF-8 | 문자에 부여한 번호와 그 번호의 인코딩 방식을 구분한다. |
| 엔디언 | 여러 바이트의 저장 순서이지 개별 바이트 안의 비트 반전이 아니다. |

계산 문제에서는 먼저 여백에 비트 수 / 부호 해석 / 소수점 위치를 적어두면 실수를 줄일 수 있다. 시프트나 자리올림 처리도 이 조건을 정한 뒤 수행한다.

## 3. 예시 문제

### 문제 1. 진법 변환

### 문제 2. 2의 보수

-37의 8비트 2의 보수 표현은?

① 10100101　② 11011010　③ 11011011　④ 00100101

### 문제 3. 표현 범위

8비트 1의 보수 표현의 범위와 0의 표현 개수로 옳은 것은?

① -128~127, 1개　② -127~127, 2개　③ 0~255, 1개　④ -127~128, 2개

### 문제 4. 오버플로

### 문제 5. 자리올림

8비트 연산 `11111111 + 00000001`의 결과가 `00000000`이고 바깥 자리올림이 1이었다. 옳은 설명은?

① 부호 없는 해석과 2의 보수 해석 모두 오버플로다.
② 부호 없는 해석에서는 오버플로지만 2의 보수 해석에서는 아니다.
③ 2의 보수 해석에서만 오버플로다.
④ 두 해석 모두 오버플로가 아니다.

### 문제 6. 고정소수점

8비트 2의 보수 정수에 배율 2⁻⁴을 적용하는 고정소수점 형식이다. `11101000`의 실제 값은?

① -1.5　② -6　③ 14.5　④ 232

### 문제 7. 부동소수점 해석

IEEE 754 단정도에서 부호가 1, 지수 필드가 `10000001`, 소수 필드가 `01000000000000000000000`일 때 값은?

① -2.5　② -5　③ -10　④ +5

### 문제 8. 특수값

IEEE 754 단정도에서 지수 필드가 모두 1이고 소수 필드가 0이 아닐 때 의미는?

① 0　② 비정규수　③ 무한대　④ NaN

### 문제 9. BCD와 문자 코드

① 10진수 59의 8421 BCD는 00111011이다.
② ASCII는 16비트 코드다.
③ UTF-8은 모든 유니코드 스칼라 값을 2바이트로 저장한다.
④ 10진수 59의 8421 BCD는 0101 1001이다.

### 문제 10. 부호 확장과 시프트

### 문제 11. 바이트 순서

32비트 값 `0xA1B2C3D4`를 리틀 엔디언으로 주소 200부터 저장한다. 주소 200과 203에 저장되는 바이트를 각각 쓰시오.

### 문제 12. 부동소수점 표현

6.5를 IEEE 754 단정도로 표현할 때 부호, 지수, 소수 필드를 각각 쓰시오.

## 4. 정답과 해설

### 문제 1 — ②

정수 부분은 `32+8+4+1=45`, 소수 부분은 `1/2+1/8=0.625`이므로 45.625다. ①은 마지막 소수 비트를 빠뜨렸다. ③은 정수부 계산이 틀렸으며, ④의 0.75는 이진 소수 0.11에 해당한다.

### 문제 2 — ③

`37 = 00100101`이다. 반전한 `11011010`에 1을 더하면 `11011011`이 된다. ①은 부호와 절댓값 표현, ②는 1의 보수 표현, ④는 +37이다.

### 문제 3 — ②

1의 보수는 양수와 음수의 크기 범위가 대칭이며 +0과 -0이 존재한다. ①은 2의 보수, ③은 부호 없는 정수의 설명이다. ④처럼 양수 쪽에 128을 추가로 표현하지 않는다.

### 문제 4 — ③

100+60=160은 최댓값 127을 넘는다. 저장되는 비트열은 `10100000`이며 2의 보수로 읽으면 -96이므로 부호가 뒤집힌다. ①은 0, ②는 -30, ④는 -120으로 모두 범위 안에 있다. 같은 부호를 더한다고 항상 오버플로가 발생하는 것은 아니다.

### 문제 5 — ②

부호 없이 읽으면 255+1=256이므로 8비트 범위를 넘는다. 2의 보수로 읽으면 -1+1=0이므로 정확한 결과다. ①·③은 최종 자리올림을 부호 있는 오버플로와 혼동했고, ④는 부호 없는 최댓값을 넘는다는 점을 놓쳤다.

### 문제 6 — ①

`11101000`을 부호 없이 읽으면 232이지만 2의 보수 정수 값은 `232-256=-24`다. 여기에 배율을 적용하면 `-24/16=-1.5`다. ②는 배율이 맞지 않는다. ③은 부호 없는 값에 배율만 적용했으며, ④는 부호와 배율을 모두 무시했다.

### 문제 7 — ②

부호는 음수다. 지수 필드 129에서 127을 빼면 실제 지수는 2다. 유효숫자는 `(1.01)₂=1.25`이므로 `-1.25×2²=-5`다. ①과 ③은 지수를 각각 1과 3으로 적용한 값이고, ④는 부호를 반대로 읽은 값이다.

### 문제 8 — ④

지수 필드가 모두 1일 때 소수 필드가 0이면 무한대, 0이 아니면 NaN이다. ①과 ②는 지수 필드가 모두 0인 경우에 소수 필드에 따라 나뉜다. ③은 소수 필드가 0이어야 한다.

### 문제 9 — ④

BCD는 5를 `0101`, 9를 `1001`로 따로 표현한다. ①은 일반 이진수 59다. ② ASCII는 7비트 코드다. ③ UTF-8은 1~4바이트의 가변 길이 방식이다.

### 문제 10 — 확장: 11111011(-5), 시프트: 11111101(-3)

4비트 `1011`은 `11-16=-5`다. 부호 비트 1을 왼쪽에 채워 8비트로 만들면 `11111011`이며 값은 유지된다. 한 비트 산술 오른쪽 시프트하면 왼쪽에 1을 채우고 마지막 비트를 버려 `11111101`이 된다. 이는 `253-256=-3`이다. -5/2를 0 방향으로 버린 -2와 다르다.

### 문제 11 — 주소 200: 0xD4, 주소 203: 0xA1

리틀 엔디언은 낮은 주소에 최하위 바이트부터 둔다. 주소 200부터 순서대로 D4, C3, B2, A1을 저장한다. 각 바이트 안의 비트 순서는 바꾸지 않는다.

### 문제 12 — 0 / 10000001 / 10100000000000000000000

`6.5 = (110.1)₂ = (1.101)₂×2²`다. 양수이므로 부호는 0, 지수 필드는 `2+127=129=(10000001)₂`다. 소수 필드는 선행 1을 제외한 101 뒤에 0을 채운다. 전체 비트열을 16진수로 묶으면 `0x40D00000`이다.
