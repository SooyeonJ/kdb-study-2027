## 문제 1. OS — 운영체제 (15점)

### (1) 경쟁 상태, 임계구역, 상호배제 [5점]

**모범답안**

경쟁 상태(Race Condition)는 둘 이상의 프로세스나 스레드가 공유 데이터에 동시에 접근하고, 실행 순서에 따라 최종 결과가 달라지는 현상이다. 임계구역(Critical Section)은 여러 실행 주체가 공유하는 데이터나 자원에 접근하여 읽기·수정 등의 작업을 수행하는 코드 영역을 의미한다.

계좌 잔액 갱신은 일반적으로 `잔액 읽기 → 금액 계산 → 변경된 값 저장`과 같이 여러 단계로 수행된다. 두 스레드가 동일한 잔액을 동시에 읽은 뒤 각자 계산한 값을 저장하면 한 스레드의 갱신 결과가 사라지는 Lost Update가 발생할 수 있다. 따라서 동일한 계좌 잔액을 갱신하는 임계구역에는 한 시점에 하나의 스레드만 진입하도록 상호배제를 보장해야 한다.

**핵심 키워드**
- Race Condition
- 공유 데이터
- 실행 순서에 따른 결과 변화
- Critical Section
- Mutual Exclusion
- Lost Update

**채점 기준**
- 경쟁 상태를 공유 데이터에 대한 동시 접근과 실행 순서에 따른 결과 변화로 설명: 1.5점
- 임계구역을 공유 자원에 접근하는 코드 영역으로 설명: 1점
- 잔액 갱신이 읽기·수정·쓰기의 복합 연산임을 설명: 1점
- Lost Update 등 잘못된 결과 가능성 설명: 0.5점
- 상호배제 필요성을 논리적으로 연결: 1점

**부분점수 유의사항**
- 단순히 “동시에 접근하면 오류가 난다”라고만 기술하고 실행 순서 또는 공유 데이터와의 관계를 설명하지 않으면 일부만 인정한다.
- 임계구역을 “프로세스가 실행되는 구역”처럼 포괄적으로만 설명하면 감점한다.

**보충 해설**

단일 CPU 환경에서도 경쟁 상태는 발생할 수 있다. 하나의 고급언어 문장이 실제로 여러 기계어 명령으로 실행되는 동안 문맥 교환이 발생할 수 있기 때문이다. 따라서 동시성 문제는 물리적으로 CPU가 여러 개인 경우에만 발생하는 것이 아니다.

### (2) Mutex와 Semaphore [5점]

**모범답안**

Mutex는 공유 자원에 대한 상호배제를 위해 사용하는 동기화 도구로, 일반적으로 하나의 실행 주체가 Lock을 획득하면 다른 실행 주체는 해당 Lock이 해제될 때까지 임계구역에 진입할 수 없다. 또한 보통 Lock을 획득한 스레드가 직접 해제하는 소유권 개념을 가진다.

Semaphore는 정수형 카운터를 이용하여 동시에 접근할 수 있는 실행 주체의 수를 제어하는 동기화 기법이다. Binary Semaphore는 0과 1의 값을 사용하여 상호배제 용도로 사용할 수 있고, Counting Semaphore는 여러 개의 동일 자원에 대한 동시 접근 수를 제한하는 데 적합하다.

이 문제에서는 하나의 계좌 잔액을 한 시점에 하나의 스레드만 갱신해야 하므로 Mutex가 가장 직접적인 선택이다. 계좌별 Mutex를 사용하면 해당 계좌의 임계구역에 하나의 스레드만 진입하도록 할 수 있고, Lock의 소유권을 명확하게 관리할 수 있다.

**핵심 키워드**
- Mutex
- 상호배제
- Lock 소유권
- Semaphore
- 카운터
- Binary Semaphore / Counting Semaphore
- 동시 접근 수 제한

**채점 기준**
- Mutex의 상호배제 기능 설명: 1.5점
- Mutex의 소유권 또는 Lock/Unlock 특성 설명: 0.5점
- Semaphore의 카운터 기반 동기화 설명: 1점
- Binary/Counting Semaphore 차이 또는 동시 접근 수 제어 설명: 1점
- 단일 계좌 갱신 상황에서 Mutex가 적절하다는 판단과 근거: 1점

**부분점수 유의사항**
- Binary Semaphore도 상호배제를 구현할 수 있으므로 이를 답으로 제시한 경우, 동시 접근을 1로 제한한다는 논리가 정확하면 일부 또는 전부 인정할 수 있다.
- “Mutex는 1, Semaphore는 여러 개”라고만 쓰고 소유권·카운터의 차이를 설명하지 않으면 감점한다.

**보충 해설**

Mutex와 Binary Semaphore는 겉으로 비슷하게 보이지만 의미가 완전히 같지는 않다. Mutex는 일반적으로 Lock의 소유자가 해제하는 상호배제 도구이고, Semaphore는 신호와 자원 개수 제어를 위한 카운터 개념이 중심이다. 시험에서는 단순히 값의 범위만 외우기보다 사용 목적과 동작 차이를 함께 설명하는 것이 좋다.

### (3) 교착상태, 예방, 기아와의 차이 [5점]

**모범답안**

제시된 상황은 교착상태(Deadlock)에 해당한다. 스레드 A는 계좌 X의 Lock을 보유한 채 Y의 Lock을 기다리고, 스레드 B는 계좌 Y의 Lock을 보유한 채 X의 Lock을 기다리므로 서로가 보유한 자원이 해제되기만을 기다리며 더 이상 진행할 수 없다.

교착상태가 발생하기 위한 네 가지 필요조건은 다음과 같다.

1. **상호배제(Mutual Exclusion)**: 하나의 자원을 한 번에 하나의 실행 주체만 사용할 수 있다.
2. **점유 대기(Hold and Wait)**: 자원을 하나 이상 보유한 상태에서 다른 자원을 추가로 기다린다.
3. **비선점(No Preemption)**: 이미 할당된 자원을 강제로 회수할 수 없다.
4. **순환 대기(Circular Wait)**: 실행 주체들이 원형으로 서로 다음 실행 주체가 보유한 자원을 기다린다.

이 시스템에서는 모든 스레드가 계좌 Lock을 항상 동일한 순서로 획득하도록 규칙을 정하는 방법을 사용할 수 있다. 예를 들어 계좌번호가 작은 계좌의 Lock을 먼저 획득하고 큰 계좌의 Lock을 나중에 획득하도록 하면 순환 대기 조건을 제거하여 교착상태를 예방할 수 있다.

기아(Starvation)는 특정 프로세스나 스레드가 다른 실행 주체에게 계속 우선순위를 빼앗겨 오랫동안 자원이나 CPU를 할당받지 못하는 상태이다. 반면 교착상태는 둘 이상의 실행 주체가 서로의 자원을 기다리면서 관련 실행 주체 모두가 진행하지 못하는 상태이다.

**핵심 키워드**
- Deadlock
- Mutual Exclusion
- Hold and Wait
- No Preemption
- Circular Wait
- Lock Ordering
- Starvation
- 무한 대기

**채점 기준**
- 제시 상황이 상호 Lock 대기로 인한 교착상태임을 설명: 1점
- 교착상태 4가지 필요조건을 정확히 제시하고 의미를 설명: 2점
- Lock 획득 순서 통일 등 타당한 예방 방법 제시 및 순환대기 제거 설명: 1점
- Starvation과 Deadlock의 차이 설명: 1점

**부분점수 유의사항**
- “Timeout을 둔다”는 방법은 실무적 대응이 될 수 있으나, 교착상태의 필요조건을 구조적으로 제거하는 예방 기법과는 구분해야 한다.
- Banker's Algorithm을 제시했다면 이는 일반적으로 교착상태 예방이 아니라 회피(Avoidance) 기법으로 분류하므로 표현에 유의한다.

**보충 해설**

교착상태의 네 조건은 모두 동시에 성립해야 한다. 따라서 예방은 네 조건 중 하나를 깨는 방향으로 설계할 수 있다. 이 사례에서 Lock Ordering은 순환 대기를 제거하는 대표적 방법이다.

기아는 시스템 전체가 멈춘 것은 아니라는 점이 중요하다. 다른 프로세스나 스레드는 계속 진행할 수 있지만 특정 실행 주체만 지속적으로 선택되지 못할 수 있다.

## 문제 2. AI — 인공지능·머신러닝 (10점)

### (1) 지도학습·비지도학습, 분류·군집화 [5점]

**모범답안**

과제 A는 과거 고객의 이탈 여부라는 정답(Label)이 존재하는 데이터를 이용하여 신규 고객의 이탈 여부를 예측하므로 지도학습(Supervised Learning)에 해당하며, 그중 분류(Classification) 문제이다.

과제 B는 사전에 정해진 정답이 없는 고객 데이터를 특성의 유사성에 따라 여러 집단으로 나누므로 비지도학습(Unsupervised Learning)에 해당하며, 군집화(Clustering) 문제이다.

분류는 정답 Label이 포함된 학습 데이터를 이용하여 새로운 데이터가 미리 정의된 범주 중 어느 범주에 속하는지 예측하는 것이 목적이다. 반면 군집화는 정답 Label 없이 데이터 간의 유사도나 거리 등을 이용하여 내부적으로 비슷한 데이터끼리 집단을 형성하고 데이터의 숨겨진 구조나 패턴을 탐색하는 것이 목적이다.

**핵심 키워드**
- 과제 A: 지도학습, 분류
- 과제 B: 비지도학습, 군집화
- Label 존재 여부
- 미리 정의된 클래스 예측
- 유사한 데이터 그룹 형성

**채점 기준**
- 과제 A를 지도학습·분류로 정확히 식별: 1점
- 과제 B를 비지도학습·군집화로 정확히 식별: 1점
- 분류의 Label 존재 및 미리 정의된 범주 예측 설명: 1.5점
- 군집화의 Label 부재 및 유사성 기반 그룹 형성 설명: 1.5점

**부분점수 유의사항**
- “분류는 예측, 군집화는 그룹화” 정도만 쓰고 Label 유무를 설명하지 않으면 일부만 인정한다.
- 군집화 결과의 군집 번호 자체는 사전에 의미가 정해진 정답 클래스가 아니라는 점에 유의한다.

**보충 해설**

지도학습은 입력과 정답의 관계를 학습한다. 대표적으로 분류와 회귀가 있다. 비지도학습은 명시적 정답이 없는 데이터에서 구조를 찾는 방식이며 군집화, 차원축소 등이 대표적이다.

### (2) 과적합과 일반화 [5점]

**모범답안**

학습 데이터에서 98%의 높은 정확도를 보였지만 검증 데이터에서 76%로 성능이 크게 떨어진 현상은 과적합(Overfitting)으로 볼 수 있다. 과적합은 모델이 학습 데이터의 일반적인 패턴뿐 아니라 잡음이나 우연한 특성까지 지나치게 학습하여, 학습 데이터에서는 높은 성능을 보이지만 새로운 데이터에서는 성능이 저하되는 현상이다.

일반화(Generalization)는 학습에 사용하지 않은 새로운 데이터에서도 안정적으로 좋은 성능을 내는 능력을 의미한다. 과적합을 완화하고 일반화 성능을 높이기 위한 방법으로는 다음과 같은 방법을 사용할 수 있다.

1. 학습 데이터를 추가 확보하거나 데이터 증강을 적용한다.
2. 불필요한 변수나 모델 복잡도를 줄인다.
3. L1·L2 등의 정규화(Regularization)를 적용한다.
4. 검증 성능이 악화되기 전에 학습을 중단하는 조기 종료(Early Stopping)를 사용한다.
5. 교차검증(Cross Validation)을 활용해 모델과 하이퍼파라미터를 보다 안정적으로 선택한다.

**핵심 키워드**
- Overfitting
- 학습 성능 높음 / 검증 성능 저하
- Generalization
- 데이터 추가 또는 증강
- 모델 단순화
- Regularization
- Early Stopping
- Cross Validation

**채점 기준**
- 과적합을 정확히 식별: 1점
- 과적합의 의미를 학습 데이터 과도 적합과 신규 데이터 성능 저하로 설명: 1점
- 일반화의 의미를 새로운 데이터에 대한 성능으로 설명: 1점
- 완화 방법 3가지 이상 제시: 2점  
  - 타당한 방법 1개당 0.5점, 최대 2점

**부분점수 유의사항**
- 테스트 데이터를 학습 데이터에 포함시키는 방법은 일반화 성능 평가의 독립성을 훼손하므로 적절한 해결책으로 인정하지 않는다.
- 단순히 “정확도를 높인다”라고만 기술하는 것은 일반화의 설명으로 충분하지 않다.

**보충 해설**

과소적합(Underfitting)은 과적합과 반대로 모델이 너무 단순하거나 학습이 부족하여 학습 데이터의 기본적인 패턴조차 충분히 학습하지 못한 상태이다. 일반적으로 과소적합은 학습 데이터와 검증 데이터 모두에서 성능이 낮게 나타날 수 있다.

과적합은 흔히 높은 분산(High Variance), 과소적합은 높은 편향(High Bias)과 연결하여 설명할 수 있지만, IT 직군 필기 수준에서는 두 개념의 의미와 일반화 성능에 미치는 영향을 이해하는 정도가 우선이다.

- 상황과 연결되지 않은 일반론만 기술한 경우 해당 설명 요소의 일부만 인정할 수 있다.
- 기술적으로 잘못된 설명은 해당 평가 요소에서 감점한다.
- 동일한 의미의 표현은 중복 채점하지 않는다.
