## 03. 문제 출제 방식

**매주 총 10문항 / 5명 출제**

| 담당 | 문항 수 | 출제 내용 |
|---|---:|---|
| 진행 담당자 | 2문항 | DS 서술형 1 + 랜덤 약술형 1 |
| 나머지 4명 | 각 2문항 | 서로 다른 2과목에서 각 1문항 |
| **합계** | **10문항** | |

### 출제 범위 및 기준

| 코드 | 과목명 |
|---|---|
| CA | 전자계산기구조 |
| OS | 운영체제 |
| NW | 데이터통신·네트워크 |
| SC | 정보보호 |
| DS | 자료구조·알고리즘 |
| DB | 데이터베이스 |
| SE | 소프트웨어공학 |
| PL | 프로그래밍언어 |
| AI | 인공지능·머신러닝 |

**1. 진행 담당자 : DS 서술형 + 랜덤 약술형**

- DS 서술형 1문항 : 산업은행 40점 기출 형식, 소문항 4개 수준의 종합형 문제
- 랜덤 약술형 1문항 : 전공 범위 내 자유 출제, 다른 과목과 중복 가능
- DS 문제는 7·9급 전산직 기출 및 알고리즘·코드 문제 참고

**2. 나머지 4명 : CA·OS·NW·SC·DB·SE·PL·AI**

- 각자 서로 다른 2개 과목에서 각 1문항, 총 8문항 출제
- 동일 주차 내 8개 과목 중복 없이 배정
- 세부 배정은 [월별 스터디 일정](./monthly/2026-11/README.md) 참고
- 산업은행뿐 아니라 전산학 전체 범위에서 출제

**공통 출제 원칙**

- 문제별 출처·정답·해설·채점 기준 작성
- 해설 작성 시 핵심 키워드 및 부분점수 기준 명시 (AI 활용 가능)
- 불참 시에도 담당 문제 출제를 기본 원칙으로 검토

## 04. 주간 운영 및 진행 절차

**마감시간 : 매주 수·목·금요일 23:59**

| 기한 | 진행 내용 | 담당 |
|---|---|---|
| **매주 수요일** | 스터디룸 예약 및 비용 정산 완료 | 진행 담당자 |
| **매주 목요일** | 문제(MD)·해설(PDF) 업로드 | 전원 |
| **매주 목요일** | 참석·불참 여부 최종 확인 | 전원 |
| **매주 금요일** | 전체 10문항 취합 및 최종본 준비 | 진행 담당자 |
| **스터디 당일** | 손필기 풀이 → 상호 채점 → 해설·피드백 | 전원 |

**예약 및 불참 규정**

- 스터디룸 비용은 참석 인원 기준 N분의 1 정산
- 예약 확정 후 불참 시 **비용 재정산·환급 불가**
- 불참 여부 사전 공유 및 목요일 최종 확인

### 진행 담당자 역할

1. 스터디룸 예약·비용 정산 및 참석 여부 확인
2. DS 서술형 1문항 + 랜덤 약술형 1문항 출제
3. 나머지 8문항(`.md`) 취합 및 최종 문제지·해설지(`.pdf`) 구성
4. 공통 답안지·출제자별 채점표 준비
5. 모임 진행 및 해설·피드백 관리

### 스터디 당일 풀이 및 채점

- 제한시간 내 오프라인 손필기 서술형 풀이
- 동일한 답안지를 활용한 상호 채점
- 모범답안·핵심 키워드·부분점수 기준에 따라 정량적 점수 산출
- 출제자 해설·피드백, 취약 개념 정리 및 다음 주 일정 확인

## 06. GitHub 자료 관리

**Repository 구조**

- `README.md` : 공통 운영 규칙
- `monthly/` : 월별 일정·과목 배정·공지
- `weekly/` : 회차별 문제·정답·해설·피드백
- `members/` : 개인별 학습 계획·일일 인증·문제 풀이
- `resources/` : 기출·참고 자료

**파일 관리 규칙**

- 회차별 폴더 : `wkNN_YYMMDD`
- 예시 : `wk01_261107`, `wk02_261115`
- 문제 파일 예시 : `wk02_OS_수연.md`
- 해설 파일 예시 : `wk02_OS_수연_해설.pdf`
- 문제·해설 별도 관리, 파일명에 출제자·과목 명시
- 진행 담당자가 최종 문제지·정답지 취합
- 모임에서 나온 질문·수정 사항은 해당 회차에 기록
- 개인 학습 계획·일일 인증·오답 기록은 개인별 자율 관리
